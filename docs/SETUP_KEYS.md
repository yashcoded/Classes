# Setup keys and environment variables

Step-by-step instructions for backend and frontend (mobile), including where each key is used and where to get or set it.

---

## Overview

| Variable | App | Where to get it | Where to set it |
|----------|-----|-----------------|-----------------|
| `PORT` | Backend | You choose (default 3000) | `backend/.env` or host |
| `JWT_SECRET` | Backend | You generate it | `backend/.env` or host |
| `JWT_EXPIRES_IN` | Backend | You choose (e.g. 7d) | `backend/.env` or host |
| `QR_SECRET` | Backend | You generate it | `backend/.env` or host |
| `EXPO_PUBLIC_API_URL` | Mobile | Your backend URL | `mobile/.env` |

There are **no third-party API keys** (no Google, Stripe, etc.). All values are either generated by you or your backend URL.

---

## Backend

### 1. Where env is loaded

- The backend loads a `.env` file from the **backend** folder at startup via [dotenv](https://github.com/motdotla/dotenv#readme).
- File to create: `backend/.env` (copy from `backend/.env.example`).

### 2. Keys and where they're used

| Variable | Required | Default | Where it's used in code | How to get it |
|----------|----------|---------|-------------------------|----------------|
| **PORT** | No | 3000 | `backend/src/server.ts` | Pick a port (e.g. 3000). Set only if you need a different one. |
| **JWT_SECRET** | Yes in production | dev default in code | `backend/src/lib/auth/jwtProvider.ts` | **Generate it:** use a long random string (e.g. 32+ chars). See "Generating secrets" below. |
| **JWT_EXPIRES_IN** | No | 7d | `backend/src/lib/auth/jwtProvider.ts` | Choose expiry: `7d`, `24h`, `30m`, etc. |
| **QR_SECRET** | Yes in production | dev default in code | `backend/src/services/sessionService.ts` | **Generate it:** same as JWT_SECRET. See "Generating secrets" below. |

### 3. Where to find / set backend keys

- **Local:** Create `backend/.env` (copy `backend/.env.example`). Put each variable on its own line, e.g. `JWT_SECRET=your-secret`.
- **Deployed on AWS:** Set environment variables in the service you use to run the backend. Optionally store secrets in **AWS Secrets Manager** or **SSM Parameter Store** and inject them at runtime.
  - **New to AWS?** See [How to use AWS (beginner-friendly guide)](AWS_NAVIGATION.md) — where to sign in, where to click, and how to find env vars for each service (Elastic Beanstalk, App Runner, Lambda, ECS, EC2).
  - **AWS Elastic Beanstalk:** [Configuration → Environment properties](https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/environments-cfgsoftwaresettings.html) — add `JWT_SECRET`, `QR_SECRET`, `PORT`, `JWT_EXPIRES_IN`.
  - **AWS App Runner:** [Configure service → Environment variables](https://docs.aws.amazon.com/apprunner/latest/dg/configuring-service.html) (or use Secrets Manager).
  - **Amazon ECS (Fargate):** [Task definition → Environment](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_definitions.html) or [Secrets (Secrets Manager / SSM)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/specifying-sensitive-data.html).
  - **AWS Lambda (Node):** [Function configuration → Environment variables](https://docs.aws.amazon.com/lambda/latest/dg/configuration-envvars.html); for secrets use [Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html) or [Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html).
  - **EC2 (e.g. Docker):** Set in your process manager or in a `.env` file on the instance (keep it out of the image); or use [EC2 Instance Connect / SSM](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html) and Parameter Store.

### 4. Generating secrets (JWT_SECRET, QR_SECRET)

**Full instructions and references:** See **[How to generate JWT_SECRET and QR_SECRET](GENERATE_SECRETS.md)** — what they are, why they must be random, and step-by-step methods (PowerShell, Node, OpenSSL, online) with links to JWT/OWASP docs.

Short version: generate **two different** long random strings (e.g. 32+ chars). Use one for `JWT_SECRET`, one for `QR_SECRET`. Never commit `.env`; only commit `.env.example`.

## Frontend (Mobile)

### 1. Where env is loaded

- Expo loads `.env` from the **mobile** folder. Only variables starting with **EXPO_PUBLIC_** are available in the app.
  - Docs: [Expo: Environment variables](https://docs.expo.dev/guides/environment-variables/).

### 2. Keys and where they're used

| Variable | Required | Default | Where it's used in code | How to get it |
|----------|----------|---------|-------------------------|----------------|
| **EXPO_PUBLIC_API_URL** | No* | http://localhost:3000/api/v1 | `mobile/src/services/api.ts` | **Your backend base URL** (no trailing slash). |

\* Required when the app runs on a device or emulator that can't reach `localhost` (use your machine's IP or your deployed backend URL).

### 3. Where to find / set frontend keys

- **Local:** Create `mobile/.env` (copy `mobile/.env.example`). Set e.g.  
  `EXPO_PUBLIC_API_URL=http://localhost:3000/api/v1`  
  or for a device on the same network:  
  `EXPO_PUBLIC_API_URL=http://192.168.x.x:3000/api/v1`.
- **Finding your backend URL:**
  - Local: `http://localhost:3000/api/v1` (or `http://YOUR_IP:3000/api/v1` for device).
  - **AWS:** Use the URL of your backend service — e.g. Elastic Beanstalk environment URL, App Runner service URL, API Gateway invoke URL, or the ALB/CloudFront URL in front of ECS/EC2. Find it in the AWS console (e.g. **Elastic Beanstalk → Environment → URL**; **App Runner → Service URL**; **API Gateway → Stages → Invoke URL**).
- Restart the Expo dev server after changing `.env`.

---

## Quick checklist

- [ ] Copy `backend/.env.example` → `backend/.env`; set `JWT_SECRET` and `QR_SECRET` (and optionally PORT, JWT_EXPIRES_IN).
- [ ] Copy `mobile/.env.example` → `mobile/.env`; set `EXPO_PUBLIC_API_URL` if not using localhost (e.g. device or production backend).
- [ ] Do not commit `backend/.env` or `mobile/.env` (they are in `.gitignore`).

## Production publish guide (AWS + Expo + Google)

Use this section when you want to actually publish, not only run locally.

### 1) Backend keys (AWS)

Set these in `backend/.env` locally, and then set the same values in AWS service env vars (for Elastic Beanstalk: Environment -> Configuration -> Software -> Environment properties).

| Key | Required | How to get it | Example |
|-----|----------|---------------|---------|
| `PORT` | Yes | You choose (Node backend default is 3000) | `3000` |
| `JWT_SECRET` | Yes | Generate random string (see command below) | `base64-random-32-bytes` |
| `JWT_EXPIRES_IN` | Optional | You choose token lifetime | `7d` |
| `QR_SECRET` | Yes | Generate random string (different from JWT_SECRET) | `base64-random-32-bytes` |
| `GOOGLE_CLIENT_IDS` | If Google login enabled | From Google OAuth Credentials page (Web/iOS/Android client IDs) | `web.apps.googleusercontent.com,ios.apps...,android.apps...` |

Generate strong secrets (PowerShell):

```powershell
node -e "const c=require('crypto');console.log('JWT_SECRET='+c.randomBytes(32).toString('base64'));console.log('QR_SECRET='+c.randomBytes(32).toString('base64'));"
```

### 2) Frontend keys (Expo mobile)

Set these in `mobile/.env` (or Expo/EAS secret envs for CI builds).

| Key | Required | How to get it | Example |
|-----|----------|---------------|---------|
| `EXPO_PUBLIC_API_URL` | Yes for real devices/publish | Your deployed backend base URL + `/api/v1` | `https://my-env.us-east-1.elasticbeanstalk.com/api/v1` |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | If Google login enabled | Google Cloud OAuth -> Web client | `123....apps.googleusercontent.com` |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | If Google login enabled | Google Cloud OAuth -> iOS client | `123....apps.googleusercontent.com` |
| `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` | If Google login enabled | Google Cloud OAuth -> Android client | `123....apps.googleusercontent.com` |

Important:

- Mobile env files must not include backend secrets like `JWT_SECRET` or `QR_SECRET`.
- Only `EXPO_PUBLIC_*` variables are exposed to the app at runtime.

### 3) How to get Google keys (OAuth IDs)

1. Open [Google Cloud Console](https://console.cloud.google.com/), create/select project.
2. APIs & Services -> OAuth consent screen:
   - App type: External (for normal testing).
   - Add scopes: `openid`, `email`, `profile`.
3. APIs & Services -> Credentials -> Create credentials -> OAuth client ID.
4. Create 3 clients:
   - Web application -> copy client ID to `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`.
   - iOS -> use app bundle ID -> copy to `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`.
   - Android -> use package name + SHA-1 -> copy to `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID`.
5. Backend `GOOGLE_CLIENT_IDS` must include all IDs used by mobile:

```env
GOOGLE_CLIENT_IDS=WEB_ID.apps.googleusercontent.com,IOS_ID.apps.googleusercontent.com,ANDROID_ID.apps.googleusercontent.com
```

If redirect URI errors appear, use the URI shown in Expo error output and add it under Google OAuth Web client -> Authorized redirect URIs.

### 4) How to get backend URL for `EXPO_PUBLIC_API_URL`

- Elastic Beanstalk: Environment page -> top URL (append `/api/v1`)
- App Runner: Service URL (append `/api/v1`)
- ECS/EC2 behind ALB/API Gateway: public endpoint + `/api/v1`

Health check first:

```text
https://<backend-host>/health
```

Should return `{ "status": "ok" }`.

### 5) Ordered release flow

1. Rotate/set backend secrets (`JWT_SECRET`, `QR_SECRET`).
2. Deploy backend to AWS — if you use **Elastic Beanstalk** and have not created an environment yet, follow **[Elastic Beanstalk from scratch](ELASTIC_BEANSTALK.md)** (build, zip, console steps, Mumbai `ap-south-1`, env properties).
3. Set backend env vars in AWS (`PORT`, `JWT_SECRET`, `QR_SECRET`, optional `JWT_EXPIRES_IN`, and `GOOGLE_CLIENT_IDS` if used).
4. Confirm backend health endpoint works.
5. Set mobile `EXPO_PUBLIC_API_URL`.
6. Set mobile Google IDs (`EXPO_PUBLIC_GOOGLE_*`) if using Google sign-in.
7. Restart Expo dev server and test login/register flows.
8. Build and publish with EAS.
